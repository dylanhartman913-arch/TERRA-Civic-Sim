# T4 / C2.1 — county hazard baseline + delta surface

## Scope and method

Notebook 24 now has a separately marked `## C2.1` addendum. It writes
`data/processed/county_climate_baseline.json` from the attributed C1.6
projection rows. No source observations were fetched and no model, sample, or
statistical fit was added.

For every `(GEOID, metric, percentile, lens)`, C2.1 algebraically inverts the
four C1.6 epoch-doctrine equations for 2030, 2040, 2050, and 2065 to recover
the historical (1991–2020) window. Its canonical county baseline is the
arithmetic mean of the separately recovered `ssp245` and `ssp370` historical
values. Both lens derivations are retained because the difference arises from
already-rounded C1.6 projected values. Every delta is exactly:

`projected_value - canonical_historical_baseline`

## Versioned data contract

Output path: `data/processed/county_climate_baseline.json`.

Top-level object, schema version `C2.1.0` (all listed properties are required):

| Field | Type / allowed value | Meaning |
|---|---|---|
| `schema_version` | string, exactly `C2.1.0` | Contract version for C5b. |
| `source_schema_version` | string, exactly `C1.6` for this output | Upstream projection contract version. |
| `baseline_reference` | object `{epoch, window, derivation}` | `historical`, `1991-2020`, and the stated arithmetic derivation. |
| `units` | object `metric -> unit string` | Unit registry for every metric. |
| `metrics` | string array | Complete set of metric keys represented in the output. |
| `lenses` | string array | `ssp245`, `ssp370`. |
| `epochs` | string array | `2030`, `2040`, `2050`, `2065`. |
| `baselines` | array of baseline records | One per available `(geoid, metric, percentile)`. |
| `deltas` | array of delta records | One per C1.6 `(geoid, metric, lens, epoch, percentile)` projection row. |

A baseline record has required fields `geoid` (five-character FIPS string),
`county_name` (string), `state` (two-character string), `metric` (one member
of `metrics`), `unit` (the corresponding `units[metric]`), `lens` (exactly
`historical`), `scenario` (exactly `historical`), `epoch` (exactly
`historical`), `percentile` (`p10`, `p50`, or `p90`), `value` (number),
`source` (string), `method` (exactly
`c2_1_epoch_doctrine_linear_system_back_derivation_then_lens_mean`),
`confidence` (string), `downscaling_method` (string or null copied from C1.6),
and `lens_derivations` (object with numeric `ssp245` and `ssp370` members).

A delta record has required identity fields `geoid`, `county_name`, `state`,
`metric`, `unit`, `lens` (`ssp245` or `ssp370`), `scenario` (equal to `lens`),
`epoch` (one member of `epochs`), and `percentile` (`p10`, `p50`, or `p90`).
Its required value/attribution fields are `value` (number; the delta),
`source` (string copied from the C1.6 projected row), `method` (exactly
`c2_1_arithmetic_projection_minus_historical_baseline`), `confidence` (string
copied from the C1.6 projected row), and `downscaling_method` (string or null
copied from the C1.6 projected row). Required audit fields are `baseline_key`
(three-string array `[geoid, metric, percentile]`), `baseline_value` (number),
`projected_value` (number), and `baseline_attribution` (object containing the
baseline's `lens`, `scenario`, `epoch`, `percentile`, `source`, `method`,
`confidence`, and `downscaling_method`). C5b must use `baseline_key` to join
the one matching baseline and must not substitute a baseline from another
percentile.

Thus every output value has C1.6 popover fields: `scenario`, `epoch`,
`percentile`, `source`, `method`, and `confidence`. The full historical
attribution is also nested on each delta; no field is defaulted when upstream
data are absent.

including all counties and both lenses. The additive design also covers the
other currently available C1.6 climate/hazard metrics listed in `metrics`; it
does not claim that any absent future metric has a baseline.
