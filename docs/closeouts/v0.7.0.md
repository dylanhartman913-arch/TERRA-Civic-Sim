### F8 — Session drought ordering (S3, commit `adcd421`) — PARTIALLY resolved

> **Read this section together with F8-LIVE, immediately below.** What follows
> describes the S3 fix accurately and is worth surfacing on its merits. But the
> fix covered `replay.ts` and one of three `store.ts` sites. **F8 is not closed.**
> This section is retained unaltered, rather than rewritten, because the gap
> between how convincing it reads and what it actually established is the
> lesson.

**The most instructive finding in Wave 7 — in more ways than intended.**

**The defect.** Session drought was applied *after* `engineAdvanceYear`, so
`advanceCountyAg` — which runs inside `advanceYear` and records the ag
trajectory snapshots — read a state with no drought in it. Drought had no effect
on agricultural outcomes at all.

**Why it survived so long.** The golden fixture had been generated from the buggy
code, so all 9 `ag4-session-drought.test.ts` tests passed against it, and the
full 351-test parity suite was green. **The test suite was green because the
fixture encoded the bug.**

**How it was caught.** Not by a failing test, but by an equality that should have
been an inequality: the drought-enabled `ag_digest_md5` and the energy-only
`ag_digest_md5` were byte-identical at `756ec0d2d5ddf481be1331a48b38a1cb`. Two
paths that must differ did not.

**The fix.** `applySessionDrought` moved before `engineAdvanceYear`, passing
`state.year + 1` as an explicit `targetYear`; `session_drought.ts` gained the
optional `targetYear` parameter; `golden_ranch_country_2040.json` updated to
`0c537942942e306a22f04bdc44418b07`. After the fix the two digests differ,
`replay_digest` is unchanged as expected, and **no other fixture moved** — the
tightest possible evidence that the change did exactly one thing.

**The Python-side answer (DECISIONS.md, S3).** Python `advance_year` does *not*
have the bug, for a structural reason rather than by luck: callers add drought
events to state via `apply_hazard_event_consequences` *before* calling
`advance_year`, so `_advance_county_ag` reads pre-existing events correctly. No
Python fix was needed, and that was established from the code rather than assumed
from the passing suite.

**Why it belongs in a release closeout.** F8 is the project's clearest precedent
that *a green suite is not evidence of correctness when the fixture was generated
by the code under test*. That is the same shape as **D-4** (4 tests green because
a notebook has not been run) and **D-1** (an audit passing because the audit
exists). Three instances of one pattern.

**And a fourth instance, which is F8 itself.** Everything above is true and
none of it established that F8 was fixed. The evidence was a digest transition
and an unmoved-fixture check — rigorous about *effect*, silent about *extent*.
Nobody enumerated the call sites. The verification was strong enough to be
convincing and narrow enough to be wrong, which is a worse combination than
weak evidence, because weak evidence invites a second look.

## Part E — Release-level risk summary

**What is solid.** Three independent CI gates (behavioral, provenance-manifest,
attribution-slope) run on every push and are proven capable of failing. 230
Python and 351 TS tests pass, re-verified this session. 64 manifest entries with
zero hash mismatches. Eight promotion pairs byte-identical. Nine pipelines fully
documented with sources, vintages, numbered assumptions, and named gaps. No
correctness defect was found in any shipped **data** artifact.

**What a reader must not conclude.**

1. **F8 is now fixed — but not because S3 fixed it.** All five sites were
   corrected in S16a, after Part 3 found three of them broken. Replay mode had
   been showing the energy-only AG digest for drought sessions. Fixed, measured,
   and gated by a test that provably fails on the pre-fix code. **One residual:
   the comparison-mode site still has no regression gate** — `Trajectory`
   carries no ag observable (B-11). (F8-LIVE)
2. **Not "Wave 7 is closed."** W7-3's rulebook never produced; W7-4 one-third
   executed. (D-9, D-10, D-11, D-12)
3. **Not "every runtime file has a generator."** The audit reporting that
   passes because the audit exists. (D-1)
4. **Not "230/230 means the county-card provenance chain is stable."** Four of
   those tests hold only while nb14 stays un-run — and the dual-path CI gate
   would *not* catch an nb14 regression, because that pair is an unenforced
   transform pair. (D-4, D-6)
5. **Not "D5 is done."** A packet exists. No domain expert has read it. (D-5)
6. **Not "the green suite means the UI paths are covered."** S16a added the
   first store-level tests, covering replay, comparison and undo drought
   behaviour. That is 8 tests against one state container — a patch on the
   structural hole F8-LIVE fell through, not a fix for it. The rest of
   `store.ts` remains largely ungated.

**Concentration of risk.** The open items cluster in one place: **artifacts
patched at the output layer while their generators stayed stale.** D-4 (nb14
source vs. patched cards), F14 (same, earlier instance), D-1 (files tracked, no
producers), D-3 (keys recoverable only by re-running notebooks). The pipeline is
currently trustworthy in its *outputs* and not yet reproducible from its
*sources*. Every one of these is safe while notebooks are not executed and
becomes a simultaneous failure the moment they are. **A full notebook re-run is
the single highest-risk operation against this release**, and should be treated
as a dedicated session with a before/after digest plan, not as routine
maintenance.

**A second concentration, found only in Part 3.** The UI-layer state container
(`store.ts`) was effectively untested, and three drought-handling defects lived
there. The project gates its *engine* rigorously — five digest contracts,
dual-path identity, manifest hashes — and gated its *store* not at all. F8-LIVE
was the first defect found in that gap; S16a closed that instance and added the
first store-level tests, but the gap itself is only narrowed. **Assume more
defects live in the untested remainder of `store.ts`.**

**Recommended gate before any "Wave 7 closed" claim:** W7-3's rulebook produced,
W7-4's three parts dispositioned, B-1/B-3/B-11 closed. *(F8-LIVE and B-6 closed
in S16a.)*

### C-5 — B-11: make the comparison-mode drought fix observable

**Disposition: OPEN. Executable by a coding session once a product call is made.
This is the one item on this list that S16a created rather than inherited.**

**Current state.** `computeTrajectory` now applies session drought
(`store.ts:261`), per the PM decision in S16a. But `Trajectory` carries only
`years`/`E`/`Ec`/`S`/`material_ledger`/`quest_conditions`/`events`, and drought
does not move E, Ec or S — measured identical at 3.1034 / 6.9341 / 5.2725 while

**Consequence, stated without softening.** The fix is real in the state the

comparison that silently omits a stochastic event one path experienced isn't
comparing the same scenario"* — is only half-served. And the site has **no
regression gate**: no honest assertion can distinguish fixed from broken there.
An ungated fix in a path that already hid one defect for five sessions is a
standing risk, not a closed item.

**Closure condition.** `Trajectory` carries a per-year ag observable (an ag
digest, drought-county count, or forage aggregate — a product call about what
comparison mode should *show*); `ComparisonView` surfaces it; and the pinned
limitation test in `f8-store-drought-sites.test.ts` is replaced by a real
regression gate that fails on drought-absent code.
