**Scope correction.** S16 Part 1 described this as "S14, S14a, S15, and S15b

All 22 are S15/S15b. S14's actual deliverable was in a worse state than

distinct and more severe defect.

**Process recommendation — push-before-session-end checklist.** Add to the Wave 7
governing documents, as a session-close gate applying to *every* session type
including documentation-only:

1. `git status --porcelain` → every intended deliverable is tracked, not `??`.
   (**This is the check that would have caught D-7**, which the push check alone
   would not.)
2. `git rev-parse HEAD origin/main` → the two SHAs are **identical**. Recording
   a local SHA does not satisfy this.
3. If they differ: `git push`, then re-run step 2.
4. Record the verified-identical SHA in the session's HANDOFF entry, phrased as
   "origin/main confirmed at `<sha>`" — not "committed as `<sha>`".
5. For documentation-only sessions, state this explicitly in HANDOFF. These
   sessions have no CI-gated artifact and therefore no automatic push trigger;
   the absence of a red build is not evidence of replication.

**Destination:** new backlog item **B-3**, to be executed against the governing

## Part C — Resolved findings worth surfacing

### F8 — Session drought ordering (closed in S3, commit `adcd421`)

**Resolved finding, and the most instructive one in Wave 7.**

**The defect.** Session drought was applied *after* `engineAdvanceYear`, so
`advanceCountyAg` — which runs inside `advanceYear` and records the ag
trajectory snapshots — read a state with no drought in it. Drought had no effect
on agricultural outcomes at all.

**Why it survived so long.** The golden fixture had been generated from the buggy
code, so all 9 `ag4-session-drought.test.ts` tests passed against it, and the
full 351-test parity suite was green. **The test suite was green because the
fixture encoded the bug.**

**How it was caught.** Not by a failing test, but by an equality that should have
been an inequality: the drought-enabled `ag_digest_md5` and the energy-only
`ag_digest_md5` were byte-identical at `756ec0d2d5ddf481be1331a48b38a1cb`. Two
paths that must differ did not.

**The fix.** `applySessionDrought` moved before `engineAdvanceYear`, passing
`state.year + 1` as an explicit `targetYear`; `session_drought.ts` gained the
optional `targetYear` parameter; `golden_ranch_country_2040.json` updated to
`0c537942942e306a22f04bdc44418b07`. After the fix the two digests differ,
`replay_digest` is unchanged as expected, and **no other fixture moved** — the
tightest possible evidence that the change did exactly one thing.

**The Python-side answer (DECISIONS.md, S3).** Python `advance_year` does *not*
have the bug, for a structural reason rather than by luck: callers add drought
events to state via `apply_hazard_event_consequences` *before* calling
`advance_year`, so `_advance_county_ag` reads pre-existing events correctly. No
Python fix was needed, and that was established from the code rather than assumed
from the passing suite.

**Why it belongs in a release closeout.** F8 is the project's clearest precedent
that *a green suite is not evidence of correctness when the fixture was generated
by the code under test*. That is the same shape as **D-4** (4 tests green because
a notebook has not been run) and **D-1** (an audit passing because the audit
exists). Three instances of one pattern.

### F8 addendum — the fix is incomplete (NEW FINDING, opened by this session)

**Disposition: NEW backlog item B-6 — must be assessed before v0.7.0 is
described as containing a complete F8 fix.**

While verifying F8's closure in current code, a **third call site** was found
retaining the pre-fix ordering. `terra-app/src/state/store.ts:1090`,
`enterReplayMode`:

```ts
state = engineAdvanceYear(state);
if (file.session_config?.drought) {
  [state] = applySessionDrought(state, file.gameSeed, file.climate_lens ?? 'historical');
}
```

Drought applied **after** `engineAdvanceYear`, and **without** the `targetYear`
argument — so `applySessionDrought` falls back to `targetYear ?? state.year`
(`session_drought.ts:35`). This is the exact pre-`adcd421` pattern.

The two sites S3 fixed are correct:

- `terra-app/src/engine/replay.ts:253` — drought at 253, `engineAdvanceYear` at
  256, `state.year + 1` passed ✓
- `terra-app/src/state/store.ts:790` — drought at 790, `engineAdvanceYear` at
  793, `preState.year + 1` passed, with an explanatory comment ✓

**Why the suite does not catch it.** `enterReplayMode` has exactly one caller —
`terra-app/src/ui/panels/SaveLoadPanel.tsx:207` — and **zero test references**.
The parity suite exercises `replay.ts`'s `replayScenario`, not the Zustand
store's replay-mode path. 351/351 is therefore consistent with this site being
broken.

**User-visible consequence (expected, not yet measured).** Scrubbing a
drought-enabled scenario in replay mode should show ag trajectory snapshots
computed without drought — diverging from the same scenario replayed through
`replay.ts`. That is a dual-path divergence in the F1/F2 class the project
specifically gates against, in a path no gate covers.

**Honest bound on this claim:** the ordering defect in the source is confirmed by
direct reading; the resulting numerical divergence is inferred from the
mechanism, not measured. Verifying it requires exercising `enterReplayMode`,
which nothing currently does. Sizing that is the first step of **B-6**.

**What is solid.** Three independent CI gates (behavioral, provenance-manifest,
attribution-slope) run on every push and are proven capable of failing. 230
Python and 351 TS tests pass, re-verified this session. 64 manifest entries with
zero hash mismatches. Eight promotion pairs byte-identical. Nine pipelines fully
documented with sources, vintages, numbered assumptions, and named gaps. No
correctness defect was found in any shipped artifact.

**What a reader must not conclude.**

1. **Not "Wave 7 is closed."** W7-3 unexecuted; W7-4 one-third executed. (D-9,
   D-10, D-11, D-12)
2. **Not "every runtime file has a generator."** The audit reporting that
   passes because the audit exists. (D-1)

   those tests plus the dual-path guarantee hold only while nb14 stays un-run.
   (D-4, D-6)
4. **Not "D5 is done."** A packet exists. No domain expert has read it. (D-5)
5. **Not "F8 is fully fixed."** Two of three call sites are. (F8 addendum)

**Concentration of risk.** The open items cluster in one place: **artifacts
patched at the output layer while their generators stayed stale.** D-4 (nb14
source vs. patched cards), F14 (same, earlier instance), D-1 (files tracked, no
producers), D-3 (keys recoverable only by re-running notebooks). The pipeline is
currently trustworthy in its *outputs* and not yet reproducible from its
*sources*. Every one of these is safe while notebooks are not executed and
becomes a simultaneous failure the moment they are. **A full notebook re-run is
the single highest-risk operation against this release**, and should be treated
as a dedicated session with a before/after digest plan, not as routine
maintenance.
