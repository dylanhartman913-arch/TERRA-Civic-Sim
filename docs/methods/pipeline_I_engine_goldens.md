## What this pipeline produces

The golden fixture suite, the fixture registry, and the Monte Carlo /
magnitude-sweep analytics. The golden fixtures are the frozen engine outputs
that define what "correct" means for every scenario the parity test suite
validates. The analytics are the sensitivity and cost-efficiency rankings that
inform which action coefficients most need domain verification.

Goldens A–L are frozen under the historical climate lens only. Golden M is the

## Five digest contracts

The golden fixtures enforce five independent digest contracts, each an MD5 hash
over a canonical JSON serialisation of a specific engine state surface:

| Digest | What it hashes | Introduced with |
|--------|---------------|----------------|
| `state_digest` | County EES (E/Ec/S), bus state summary, active couplings, SC pools, year | Golden A (v1.0) |
| `fiscal_digest` | County fiscal ledgers (A/B/C), assessed values, cumulative deltas | Golden D (v2.0) |
| `existing_assets_digest` | Generator/anchor inventory and retirement state | Golden G' (v3.1) |
| `history_digest` | IndicatorSnapshot time-series (population, working_age_population, service_funding_per_capita over n years) | Golden J' (v4.2) |
| `ag_digest` | Agricultural layer state (forage, cattle, treatment decay, drought effects) | Golden N (v4.7) |

Goldens A–C predate the multi-digest regime and carry only `state_digest`.
Goldens D–F add `fiscal_digest`. Goldens G' onward carry four digests. Golden
N introduces the fifth (`ag_digest`).

## Parity test structure

### Python tests

15 test files in `tests/`, including `test_terra_engine_v3.py`,
`test_golden_n.py`, `test_c2_exposure_tags.py`, `test_c4ii_consequences.py`.
**230 assertions** as of S11 (was 226 before the `test_county_card_capacity_
provenance.py` exclusion was removed).

### TypeScript parity tests

33 test files in `terra-app/tests/parity/`, covering golden-a through golden-n,
climate tests, session tests, anchor tests, retirement, replay integrity, and
the contract matrix. **351 assertions.**

### Test pattern

Each TS parity test follows a consistent pattern: load fixture via
`loadFixture('golden_x')`, call `loadInitialState()`, replay each step with
`applyAction()`, assert per-step EES deltas via `relClose()` tolerance, then
assert the final digest MD5 via `computeDigestMd5()`. Later goldens (D+) also
assert `computeFiscalDigestMd5()`, `computeExistingAssetsDigestMd5()`,
`historyDigest()`, and `agDigest()`.

Python tests follow the same pattern using `initialize_state()` and
`advance_year()` with `apply_action()`, asserting the same digest values
against the same shared fixture files.

### Cross-runtime parity guarantee

True cross-runtime parity is enforced structurally: both Python and TS test
suites check against the **same fixture values** in the same JSON files. If
either engine computes a different digest, its test suite fails. This is
indirect but effective — no coverage gap exists as long as both suites run on
every CI push (which they do: the pytest and parity CI jobs run in parallel).

### Recomputation on corrected baseline (S8)

Both MC and sweep were recomputed in S8 on the S7a/S7b/F14-corrected baseline.
All 15 MC ranks are identical between pre-S7a and post-S7a outputs; ρ values
differ by <0.001 (statistical noise). The sub-portfolio flip rate is 0.0 — not
a single draw changed the sub-portfolio ranking. This stability is structural:
the S7a fix corrected the Ec_gencap normalisation (a uniform baseline level
shift across 123 counties), while the MC sensitivity analysis measures relative
leverage via Spearman correlation, which is invariant to uniform shifts.

## Known gaps

### Superseded goldens retained

Goldens G (v3.0) and J (v4.0) are superseded by G' (v3.1) and J' (v4.2)
respectively, but the superseded fixture files remain in the `terra-app/tests/
parity/fixtures/` directory. They are not actively tested but occupy space.

### nb14 source regression risk

nb14's stale `FLAGSHIP_ASSETS` list (Cell 4f) affects Pipeline I indirectly:
if nb14 is re-run from source, the regressed county_cards data propagates into
any golden regeneration that depends on county_cards. The golden fixtures are
currently correct (regenerated on F14-patched data), but a future nb14 re-run
without source patching would require re-regenerating all affected goldens.

### Amendment budget exhausted

The 4-slot amendment budget is fully consumed (G→G': 2 slots, J→J': 2 slots).
Any future golden that needs to supersede an existing one would require either
expanding the budget or retiring and de-registering a superseded golden.
