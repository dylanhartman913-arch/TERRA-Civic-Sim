## build_log/ — Wave-level session and task records

Per-wave session records live in `build_log/wave{4,5,6,7}/`, **not** in `docs/`.
They are not moved here because:

1. `build_log/wave7/HANDOFF.md` and `DECISIONS.md` are **active governance docs**
   being appended to in the current wave; moving them mid-wave would break the
   session protocol.
2. `build_log/wave4/_baseline.md` is referenced by `scripts/provision_worktree.sh`
   (still the correct location for worktree provisioning).
3. The `build_log/wave*/` structure is self-consistent and already provides
   per-wave organisation. Collapsing it into `docs/session_logs/` would lose
   that structure without adding navigability.

Quick reference:

| Directory | Contents |
|-----------|---------|
| `build_log/wave4/` | `_baseline.md` (P0), `c4-i.md` (Climate Hazard ticket), `c5a.md` (Climate UI ticket) |
| `build_log/wave5/` | `_setup.md` (P0), `c5a-r.md`, `t1`–`t6` task closeouts |
| `build_log/wave6/` | `ag2-engine-lock.md`, `ag3-ui-layer.md` |
| `build_log/wave7/` | `HANDOFF.md` (active), `DECISIONS.md` (active), `snapshots/` |
